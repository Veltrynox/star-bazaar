Star Bazaar: how the work flows

Agents keep no memory between sessions, so everything passes through files. Hover a box to see what it connects to.

Rules People and main session Role agents Files and logs Generated, never edit by hand Owner starts by hand only
Loop: the owner decides, the main session briefs an agent, the agent changes files and writes a handoff, the main session reads the handoff and commits.
Hard rule: economy-designer and qa-analyst (and the economy check qa/check/run.sh, retunes, sign-offs) run only when the owner asks. sh tools/tests/run.sh is always allowed and is not QA.
Commit gates: one hook (tools/gdd_sync.py) runs three checks on every git commit, in this order. A failed check blocks the commit and tells the agent what to fix.
1. GDD sync: game/, data/ or story/ changed without gdd.md. Fix: start doc-manager to update the GDD from the diff, stage it, commit again. No design effect: put [no-gdd] in the commit command.
2. Blackboard: tools/blackboard.py moves run entries older than the last 4 from blackboard.md to logs/<stamp>-blackboard-archive.md (disposable, git-ignored; a script, never the agent; the notes are kept). A blackboard.md with a bad structure (title, "Do not repeat", "Left to do", run heading, the eight fields in order) blocks the commit.
3. Tests: a commit that changes game/, data/, story/ or tools/tests/ runs sh tools/tests/run.sh and is blocked on any FAIL. No code effect: put [no-tests] in the commit command.
